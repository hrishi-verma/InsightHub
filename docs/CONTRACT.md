# InsightHub contract — error tracking v1

The agreement every part of the system builds against. Owned by the lead; agents don't edit it.
If something here is wrong or missing, raise it in your report.

```
Education Enlightened ──(1) POST /api/v1/events──▶ backend ──(2) Kafka "error-events"──▶ processor
 (browser + API)                                        │                                  │
                                                        │                        (3) Postgres tables
dashboard ◀──────────(4) read API + login──────────────┘◀─────────────────────────────────┘
```

## 1. Ingestion API: `POST /api/v1/events`

**Auth: an API key, one of two kinds.** Keys belong to a project (e.g. `education-enlightened`).

| Kind | Format | Sent as | Used by | Rules |
| --- | --- | --- | --- | --- |
| secret | `ih_sk_` + 43 chars base64url (32 random bytes) | `Authorization: Bearer <key>` | servers | Never put in a browser: a request carrying an `Origin` header is **401** (amended 2026-10-23). Events must have `source: "server"` |
| public | `ih_pk_` + 43 chars base64url | `X-InsightHub-Key: <key>` | browsers | Request `Origin` must exactly match one of the key's `allowed_origins`, else **403**. Events must have `source: "browser"` |

Keys are looked up by SHA-256 hash and compared in constant time. Revoked keys get **401**.

**CORS:** for public keys, answer preflight (`OPTIONS`) only for origins in some active public
key's `allowed_origins`. Allow headers `Content-Type, X-InsightHub-Key`, method `POST`, no credentials.

**Body:** `Content-Type: application/json`, max **64 KB**, shape `{ "events": [Event, …] }` with
1–20 events.

**Responses**

| Status | When | Body |
| --- | --- | --- |
| 202 | Accepted (queued) | `{ "accepted": <n> }` |
| 400 | Invalid body or any invalid event (whole batch rejected) | error shape (below) |
| 401 | Missing, unknown or revoked key; both key headers sent; secret key with an `Origin` header | error shape |
| 403 | Public key from a disallowed Origin, or `source` doesn't match key kind | error shape |
| 413 | Body over 64 KB | error shape |
| 415 | Not JSON | error shape |
| 429 | Rate limited. Includes `Retry-After` (seconds) | error shape |
| 503 | Kafka unavailable (sender may retry later) | error shape |

**Error shape (all APIs):** `{ "error": { "code": "VALIDATION_ERROR", "message": "…" } }`.
Codes: `VALIDATION_ERROR`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `PAYLOAD_TOO_LARGE`,
`UNSUPPORTED_MEDIA_TYPE`, `RATE_LIMITED`, `UNAVAILABLE`, `INTERNAL`. Never include stack traces.

**Rate limits** (events, not requests; per minute):
- secret key: 600 per key
- public key: 60 per (key + client IP) and 600 per key overall

IP is used only in memory for limiting. It is never stored or logged.

### The Event (v1)

Strict: **unknown fields are rejected** (keeps accidental personal data out).

| Field | Type | Req. | Rules |
| --- | --- | --- | --- |
| `event_id` | string | ✔ | UUID v4, generated by the sender (makes retries idempotent) |
| `occurred_at` | string | ✔ | ISO 8601 with timezone. No more than 5 min in the future, no more than 7 days old |
| `source` | `"browser"` \| `"server"` | ✔ | Must match the key kind |
| `environment` | `"production"` \| `"preview"` \| `"development"` | ✔ | |
| `level` | `"fatal"` \| `"error"` \| `"warning"` | ✔ | |
| `error_type` | string | ✔ | 1–128 chars, e.g. `TypeError`. Use `Error` if unknown |
| `message` | string | ✔ | 1–1000 chars |
| `stack` | string | | ≤ 16 000 chars |
| `release` | string | | ≤ 64 chars, `[A-Za-z0-9._-]` (e.g. git SHA) |
| `url_path` | string | | ≤ 512 chars, starts with `/`, **no `?` or `#`** |
| `http` | object | | Server only: `{ "method": "GET"\|"POST"\|"PUT"\|"PATCH"\|"DELETE"\|"OPTIONS"\|"HEAD", "status": 100–599, "route": string ≤ 256 }`. All three are optional inside |
| `runtime` | string | | ≤ 64 chars, e.g. `node 24.1`, `Chrome 140` |
| `tags` | object | | ≤ 10 entries. Key `[a-z0-9_.-]{1,32}`, value string ≤ 128 |

Example:
```json
{
  "events": [{
    "event_id": "9b2f7c1e-3a4d-4e8f-9c1a-2b3c4d5e6f70",
    "occurred_at": "2026-10-11T09:30:00.000Z",
    "source": "server",
    "environment": "production",
    "level": "error",
    "error_type": "PrismaClientKnownRequestError",
    "message": "Unique constraint failed on the fields: (`email`)",
    "stack": "PrismaClientKnownRequestError: …\n    at register (/var/task/backend/services/auth.service.js:42:11)",
    "release": "07b4c36",
    "url_path": "/api/auth/register",
    "http": { "method": "POST", "status": 500, "route": "/api/auth/register" },
    "runtime": "node 24.1"
  }]
}
```

### Scrubbing on arrival (backend, before Kafka)
Senders scrub too, but the backend applies this to `message`, `stack` and tag values anyway:
- email addresses → `[email]`
- `Bearer …` / `Basic …` credentials → `[credential]`
- JWT-looking strings (`xxx.yyy.zzz` base64url) → `[jwt]`
- runs of ≥ 24 characters from `[A-Za-z0-9_-]` that are **all hex, or contain both a letter and a digit** → `[token]`
  (so long identifiers like `PrismaClientKnownRequestError` survive; amended 2026-10-11)
- IPv4/IPv6 addresses → `[ip]`
- home directories in paths (`/Users/<name>`, `/home/<name>`, `C:\Users\<name>`) → `~` (amended 2026-10-23)
- query strings and fragments inside URLs → removed (`https://a.com/x?y=1` → `https://a.com/x`)

## 2. Kafka message

- Topic **`error-events`** (separate from the legacy `logs` topic).
- Message key: the project id as a string (keeps one project's events in order on one partition).
- Value (JSON):

```json
{ "schema": 1, "project_id": 1, "received_at": "2026-10-11T09:30:01.120Z", "event": { …validated, scrubbed Event… } }
```

The message key is **required** and must be the decimal string of `project_id`. A missing,
non-numeric or mismatched key means the message is skipped and logged (amended 2026-10-23).
The processor still validates every message (strict schema). Invalid messages are logged
(without their content) and skipped, so one bad message never stops the consumer.

## 3. Database (Postgres + TimescaleDB)

Created by `database/migrations/001_error_tracking.sql` (owned by the lead). Summary:

| Table | Purpose | Key columns |
| --- | --- | --- |
| `projects` | Who sends errors | `id`, `slug` (unique), `name` |
| `api_keys` | Ingestion keys | `project_id`, `kind` (`secret`/`public`), `key_prefix` (first 12 chars, for display), `key_hash` (SHA-256 hex, unique), `allowed_origins text[]`, `revoked_at`, `last_used_at` |
| `users` | Dashboard logins | `email` (unique, lower-case), `password_hash` (bcrypt, cost ≥ 12), `role` (`admin`/`viewer`), `disabled_at` |
| `sessions` | Dashboard sessions | `token_hash` (SHA-256 of the cookie value, PK), `user_id`, `expires_at`, `last_seen_at` |
| `issues` | One row per distinct error (grouped by fingerprint) | `project_id`, `fingerprint` (unique per project), `source`, `error_type`, `title`, `culprit`, `status` (`unresolved`/`resolved`/`ignored`), `first_seen`, `last_seen`, `event_count`, `last_release`, `resolved_at` |
| `error_events` | Every occurrence (hypertable on `occurred_at`) | all Event fields + `project_id`, `issue_id`, `received_at`, `ml_score`, `ml_model_version`. PK `(event_id, occurred_at)` |
| `issue_alerts` | Alerts raised by rules | `project_id`, `issue_id`, `kind` (`new_issue`/`spike`/`regression`), `details jsonb`, `created_at`, `acknowledged_at`, `acknowledged_by` |

The legacy `logs` and `log_aggregates` tables stay as they are.

### Processing rules (processor)

**Fingerprint** = SHA-256 hex of
`project_id | source | error_type | normalized_message | frame1 | frame2 | frame3`, where:
- `normalized_message`: message with UUIDs → `<uuid>`, numbers → `<n>`, hex runs ≥ 8 → `<hex>`,
  quoted text (`'…'`, `"…"`, `` `…` ``) → `<str>`, whitespace collapsed, lower-cased
- `frameN`: the first three **in-app** stack frames (skipping frames whose file contains
  `/node_modules/` or starts with `node:` / `internal/`; if none are in-app, the first three of all
  frames; amended 2026-10-11) as `function@file`, with line/column numbers, query
  strings and build hashes in file names (e.g. `index-a1b2c3d4.js` → `index.js`) removed. Missing frames are empty strings.

`title` = `error_type: message` (first 200 chars). `culprit` = first frame from the same in-app selection (`function (file)`),
else `http.route`, else `url_path`, else empty.

**Storing an event (one transaction):**
1. Upsert the issue by `(project_id, fingerprint)` and get its id (don't count yet).
2. `INSERT … ON CONFLICT (event_id, occurred_at) DO NOTHING`. If it was a duplicate, stop.
3. Update the issue: `event_count + 1`, `last_seen = greatest(last_seen, occurred_at)`, `last_release`.

**Alert rules (transparent, configurable via env, these are the defaults):**
- `new_issue`: the issue was just created.
- `regression`: an event that **occurred after `resolved_at`** arrives for a `resolved` issue. Set it back to `unresolved` and clear `resolved_at`. A late-delivered event that occurred before the resolve is stored and counted silently.
- `spike`: events for the issue in the last 5 min ≥ max(10, 5 × its average 5-minute count over
  the previous 24 h). At most one spike alert per issue per hour.
- `ignored` issues still store events and counts but raise no alerts.

**ML (shadow only):** if `ML_SHADOW=on`, the processor may call the ML engine with a 500 ms timeout
and store `ml_score` + `ml_model_version` (`synthetic-v0`). It **never** affects alerts or status.

## 4. Dashboard API (same backend, under `/api/v1`)

**Auth:** session cookie (random 32 bytes; DB stores only its SHA-256), httpOnly, `SameSite=Strict`,
`Path=/`, no `Domain`. In production it is named **`__Host-ih_session`** and is `Secure`. In
development (plain http on localhost) it is `ih_session` without `Secure` (amended 2026-10-23).
Sessions expire after 12 h. Users are created with a CLI script (no public sign-up).

**CORS/CSRF:** credentials allowed only for origins in `DASHBOARD_ORIGINS`. Every
state-changing request must be `application/json` and have an `Origin` in `DASHBOARD_ORIGINS`,
else 403. Login is rate-limited (10 per 15 min per IP + email) with the same response time and
message for unknown email and wrong password.

| Method & path | Who | Request | Response |
| --- | --- | --- | --- |
| `POST /auth/login` | anyone | `{ email, password }` | 200 `{ user }` + cookie · 401 |
| `POST /auth/logout` | logged in | — | 204, session deleted |
| `GET /auth/me` | logged in | — | 200 `{ user }` · 401 |
| `GET /projects` | logged in | — | `{ projects: [{ id, slug, name }] }` |
| `GET /overview?project=<slug>&hours=24` | logged in | `hours` 1–168 | `{ events_total, new_issues, unresolved_issues, open_alerts, hourly: [{ hour, browser, server }], top_issues: [Issue × 5] }` |
| `GET /issues?project=<slug>&status=&source=&environment=&q=&sort=&cursor=&limit=` | logged in | `sort` = `last_seen` (default) \| `first_seen` \| `event_count`. `limit` 1–100 (default 25). `q` searches title (max 200 chars) | `{ issues: [Issue], next_cursor: string \| null }` |
| `GET /issues/:id` | logged in | — | `{ issue: Issue, hourly: [{ hour, count }] }` (last 24 h) |
| `GET /issues/:id/events?cursor=&limit=` | logged in | `limit` 1–50 (default 20) | `{ events: [Event + { received_at, ml_score, ml_model_version }], next_cursor }` |
| `PATCH /issues/:id` | **admin** | `{ status: "unresolved" \| "resolved" \| "ignored" }` | `{ issue }` |
| `GET /alerts?project=<slug>&acknowledged=false` | logged in | | `{ alerts: [{ id, kind, issue: { id, title }, details, created_at, acknowledged_at }] }` |
| `POST /alerts/:id/ack` | **admin** | `{}` | `{ alert }` |

**Clarifications (2026-10-11):**
- `POST` requests without a body (`/auth/logout`, `/alerts/:id/ack`) still send `{}` as `application/json`.
- `/alerts?acknowledged=`: `false` = open, `true` = acknowledged, omitted = all.
- `/issues?environment=`: issues with at least one event in that environment.
- `/overview`: `top_issues` = top 5 by events within the `hours` window, any status. `new_issues` =
  `first_seen` within the window. `open_alerts` = all unacknowledged (no window).
- Issue and alert `id`s are JSON integers.
- `/issues/:id`, `/issues/:id/events`, `PATCH /issues/:id` and `POST /alerts/:id/ack` accept an optional `?project=<slug>`; a mismatch is 404.
- `/alerts` returns at most 200 alerts, newest first (no cursor yet).
- The scrubber also applies to `url_path`. `http` on a `browser` event is rejected (400). Sending both key headers is 401.
- In production the dashboard and API must share a registrable domain over https (the cookie is `SameSite=Strict`).

`user` = `{ id, email, role }`. `Issue` = `{ id, project, fingerprint, source, error_type, title,
culprit, status, first_seen, last_seen, event_count, last_release }`. Timestamps are ISO 8601 UTC
strings. Cursors are opaque strings. Anything not found, or in another project, is **404**.

## 5. Admin scripts (backend)

- `npm run create-user -- --email a@b.com --role admin` asks for the password interactively
  (never as an argument). At least 12 characters and at most **72 bytes** in UTF-8, bcrypt's limit
  (amended 2026-10-23). Login rejects a password over 72 bytes with 400.
- `npm run create-key -- --project education-enlightened --kind public --origin http://localhost:5173`
  prints the key **once**. `--origin` is repeatable and required for public keys (exact origins,
  `https://` in production; `http://localhost:*` allowed only when `NODE_ENV=development`).
- `npm run revoke-key -- --prefix ih_pk_abc123`
